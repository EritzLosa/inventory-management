Factory Inventory Management System

Architecture overview: Vue 3 single-page app, FastAPI backend, JSON files loaded into memory. No database.

System architecture

Tech stack

Frontend

  • Vue 3 with the Composition API
  • Vite 8 dev server and build
  • vue-router 4, 6 routes
  • axios for HTTP
  • Custom SVG charts, CSS Grid layouts
  • i18n: English and Japanese (locales/)

Backend

  • Python 3.11+, managed with uv
  • FastAPI + Uvicorn
  • Pydantic 2 response models
  • CORS open to all origins
  • Read-only GET endpoints

Data and tooling

  • 7 JSON files, held in memory
  • No database, no persistence
  • pytest + TestClient in tests/backend
  • Claude Code agents, commands and skills in .claude/

Data flow: changing a filter

  1. The user picks a value in FilterBar (Time Period, Warehouse, Category, Order Status).
  2. useFilters updates shared singleton refs, so every view sees the same filter state.
  3. The view calls getCurrentFilters() and passes the result to api.js, which drops any all values and builds the query string.
  4. axios sends GET http://localhost:8001/api/orders?warehouse=…&month=Q3-2025.
  5. FastAPI runs apply_filters() and filter_by_month() over the in-memory lists. Quarters map to three months each.
  6. Pydantic validates the result and FastAPI returns JSON.
  7. The view stores raw data in refs (allOrders, inventoryItems), and computed properties derive the KPIs and charts.

Observations

Gaps found while mapping the code
  • api.js calls /api/tasks and /api/purchase-orders, but neither endpoint exists in main.py, so those calls return 404.
  • views/Backlog.vue exists but has no route in main.js.
  • The API base URL is hard-coded to localhost:8001 in api.js.
  • The backend filters inventory by month only on orders. Inventory has no time dimension, by design.
